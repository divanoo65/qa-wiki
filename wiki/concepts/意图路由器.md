# 意图路由器 (Intent Router)

## 概念定义
意图路由器（Intent Router）是 Harness Agent 系统中负责“理解与分发”的核心组件。在传统的自动化系统中，路由往往依赖于简单的 URL 匹配或关键词触发，这种方式被称为“URL 路由器”，其局限性在于无法处理复杂的语义需求，且容易导致系统逻辑僵化。意图路由器则通过引入 [[Hermes LLM]] 作为大脑，对用户输入的原始信息进行深度语义解析，提取出核心意图，并将其转化为系统可执行的动作序列。它不仅是连接用户输入与后端 [[SOP]] 的桥梁，更是确保系统能够根据上下文动态调整执行路径的决策中心。通过意图路由器，系统能够从“被动触发”转向“主动理解”，从而显著提升 Agent 的灵活性与准确性。

## 技术细节
意图路由器的核心实现逻辑包含以下关键技术点：

1. **动作先解析原则**：系统强制要求 `parse_intent_actions()` 函数作为处理流程的第一步。在该阶段，意图被解析为一组结构化的 `actions`，这些动作作为后续 Pipeline 执行的必传参数，确保了执行逻辑的确定性。
2. **意图契约（Intent Contract）**：为了防止逻辑漂移，每个处理意图的函数必须显式声明其支持的动作范围。这种契约机制确保了路由结果与执行函数之间的强一致性。
3. **语义映射机制**：摒弃了传统的 `if-else` 关键词匹配，转而利用 LLM 对输入进行意图分类。即使输入形式多样（如 Webhook、TG 消息或 GitHub 事件），路由器也能将其统一映射为标准化的 Pipeline 触发指令。
4. **验证闭环**：在路由过程中，验收标准不仅包含“Pipeline 是否触发”，还强制要求对输出内容进行意图符合度验证，确保最终产出符合用户的原始意图。

## 应用场景
- **多源事件分发**：当系统同时接收来自 GitHub Push、Telegram 消息或 Webhook 的请求时，意图路由器负责统一解析这些异构输入，并将其分发至对应的处理逻辑。
- **动态 Pipeline 编排**：根据用户意图的复杂程度，动态决定是否调用“内容变换”或“知识图谱构建”等可选 Stage，实现按需执行。
- **自动化测试与质量控制**：在开发阶段，通过意图路由器验证系统是否能够正确识别意图，并确保输出内容与意图保持一致，从而避免“关键词匹配”带来的逻辑错误。
