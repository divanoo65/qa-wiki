## 概念定义

流水线（Pipeline）在 Harness Agent 架构设计中指代一种**由 Brain（Hermes LLM）编排多个原子 Skill 形成的工作流模式**。其核心思想是将复杂任务拆解为一系列顺序或条件依赖的执行步骤，每个步骤由独立的 Skill 承担固定的原子操作，而决策逻辑（如顺序选择、分支判断、并行执行）则全部交由上层的 Brain 负责。这种设计使流水线既保持了流程的确定性（Skill 内部逻辑固定），又拥有全局编排的灵活性（Brain 可根据上下文动态调整执行路径）。与传统的硬编码流程不同，Harness 的流水线通过**接口虚拟化**和**配置驱动**机制实现了执行环境的抽象，使得同一个流水线可以无差别地运行在本地沙箱、远程容器或云环境中，而无需修改 Skill 的实现。流水线的本质是对“编排”概念的结构化封装：它不关注单个 Skill 的内部细节，而是关注 Skill 之间的数据传递、顺序约束和错误恢复策略。在实际应用中，一个任务往往对应一条或多条流水线，每条流水线由 Brain 根据意图实时生成或从预定义模板中实例化，从而在“完全动态”和“完全固化”之间取得了平衡。

## 技术细节

### 流水线的组成要素
- **Stage（阶段）**：流水线的基本执行单元，对应一个 Skill 实例。每个 Stage 有明确的输入输出 Schema，且内部逻辑不可修改。
- **Edge（边）**：定义 Stage 之间的依赖关系，包括顺序（前驱-后继）、条件（根据前序输出决定是否执行后继）、并行（无依赖的 Stage 同时启动）。
- **Context（上下文）**：贯穿整个流水线执行的数据载体，由 Brain 初始化并在 Stage 之间传递。Context 包含原始请求、各 Stage 输出、中间状态以及 Brain 的决策缓存。
- **Error Handler（错误处理器）**：每个 Stage 可配置失败时的回退策略（重试、跳过、终止、跳转至修复 Skill），这些策略由 Brain 在编排时动态挂载。

### 流水线的生命周期
1. **定义阶段**：Brain 根据用户意图和可用 Skill 列表，通过推理生成流水线 DAG（有向无环图）。若意图匹配预置模板，则直接复用。
2. **实例化阶段**：将 DAG 转换为可执行计划，为每个 Stage 注入实际参数（如目标仓库、API 密钥），并验证所有依赖的 Skill 就绪。
3. **执行阶段**：逐级触发 Stage 执行，每个 Stage 执行完毕后将输出写入 Context，Brain 根据执行结果决定是否调整后续流程（例如发现需额外验证时动态插入 [[内容验证]] Skill）。
4. **完成与反馈**：流水线执行完毕后，Brain 汇总所有输出和错误信息，生成最终回复或触发后续流水线。同时记录执行日志用于后续优化。

### 与 [[接口虚拟化]] 的关系
流水线的可移植性依赖于底层执行环境的归一化。通过在 Plugin 层实现统一接口（如 `RunCommand`、`ReadFile`、`WriteArtifact`），流水线中的每个 Skill 无需感知当前是本地进程、Docker 容器还是远程沙箱。这种虚拟化使得同一个流水线代码可以在不同环境中复现相同行为，极大地提升了测试和部署效率。

## 应用场景

### 1. 持续集成/持续部署（CI/CD）
Harness Agent 的流水线天然适用于传统的 CI/CD 场景：Brain 将“代码构建 → 单元测试 → 集成测试 → 部署到预发 → 冒烟测试 → 生产发布”封装为一条流水线。每个步骤对应一个 Skill（例如 `BuildSkill`、`TestSkill`、`DeploySkill`），Brain 依据测试通过情况决定是否跳过后续阶段或触发回滚。同时，流水线通过 [[配置驱动]] 机制支持多环境复用：开发环境、测试环境、生产环境共用同一 DAG 定义，仅通过配置切换目标集群。

### 2. 智能故障排查与自愈
当系统告警被触发时，Harness Agent 的流水线可以自动执行“事件分类 → 日志检索 → 根因分析 → 修复方案生成 → 审批 → 执行修复”的全链路操作。Brain 根据告警类型动态编排流水线：如果已知是磁盘满事件，则跳过日志检索直接执行 `DiskCleanupSkill`；如果根因不确定，则插入 [[Intent Router Agent]] 进行意图解析，再决定调用哪个修复 Skill。这种动态流水线大大减少了人工介入，提升了 MTTR（平均修复时间）。

### 3. 多步骤数据处理与合规检查
在金融或安全场景中，需要对用户操作进行多步骤验证：接收请求 → 身份认证 → 权限检查 → 数据脱敏 → 审计日志记录 → 业务处理。每条流水线中的 Skill 可以来自不同团队（如认证组、安全组），Brain 负责保证执行顺序和回滚一致性。利用流水线的条件边，可以只在权限失败时执行“告警通知”分支，而无需修改其他 Skill 的逻辑。
