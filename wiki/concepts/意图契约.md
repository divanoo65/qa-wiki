# 意图契约 (Intent Contract)

### 概念定义
意图契约（Intent Contract）是针对 Agent 系统架构中「意图与执行逻辑不匹配」这一设计坏味道所提出的防御性编程规范。在传统的 Agent 系统中，系统往往被错误地设计为「URL 路由器」，即仅根据触发源或路径进行简单的逻辑分发，而忽略了上层 LLM 解析出的核心意图。意图契约要求系统中的每一个处理函数或 Pipeline 模块，必须显式地声明其所支持的动作（Actions）集合。通过这种契约机制，系统能够强制要求 `parse_intent_actions()` 等解析函数在执行初期就确定动作参数，并将其作为必传项向下游传递。这不仅解决了函数签名中存在冗余参数的问题，更从根本上确保了 Agent 的执行逻辑能够严格响应用户的真实意图，而非仅仅是触发了某个 Pipeline 的流程。

### 技术细节
意图契约的实现核心在于将「意图解析」与「业务执行」进行强绑定：
1. **显式声明**：每个处理意图的函数必须包含元数据或类型定义，明确列出其支持的 `actions` 列表。
2. **强制解析**：系统架构必须保证 `parse_intent_actions()` 处于执行链路的最前端，将解析出的 `actions` 作为后续所有 `build_content()` 或执行函数的必传参数。
3. **验证机制**：在测试层面，验收标准不再局限于「Pipeline 是否触发」，而是必须包含「内容是否符合意图」的验证逻辑（例如：若意图为翻译，则必须验证输出内容是否为中文）。
4. **防范坏味道**：通过契约约束，消除代码中 `intent` 参数被传入却在内部逻辑中被忽略的无效代码，确保系统架构的纯净度。

### 应用场景
- **复杂 Agent 路由**：在涉及多阶段任务（如研究、变换、知识图谱构建）的系统中，确保每个阶段的 Agent 都能准确识别并执行用户指定的动作。
- **SOP 自动化执行**：在基于 `sop.yaml` 定义的自动化流程中，利用意图契约校验当前步骤是否具备处理特定意图的能力。
- **系统重构与解耦**：当系统从简单的 URL 路由向智能意图路由演进时，通过引入意图契约来强制执行 [[解耦原则]]，防止逻辑泄漏。
