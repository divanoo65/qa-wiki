# 健康契约 (Health Contract)

### 概念定义
健康契约（Health Contract）是一种在复杂 Pipeline 架构中用于保障系统鲁棒性的设计模式。它通过将 Pipeline 的运行状态监控与输出质量评估进行正交化处理，建立起一套明确的“契约”机制。在该机制下，系统不仅关注流程是否按预期完成（即“存活状态”），还关注产出物是否符合预设的质量标准（即“内容质量”）。健康契约的核心逻辑在于：只有当阶段守卫（Stage Guard）确认流程完整执行后，评估器（Evaluator）才会介入进行质量校验。这种分层保障机制有效避免了因流程中断导致的无效评估，同时也防止了因盲目重跑而造成的资源浪费，是构建高可靠性自动化工作流的基础。

### 技术细节
健康契约的实现依赖于两个维度的协同：
1. **流程完整性保障（Stage Guard）**：作为契约的前置条件，负责监控进程的生命周期。它通过检查执行日志（如 git log 中的 done commit）来判断阶段是否真正完成。如果 Guard 未通过，系统将直接触发异常处理，而不会进入评估环节。
2. **内容质量评估（Evaluator）**：作为契约的交付标准，在 Guard 确认完成后介入。它利用规则检查与 [[Gemini]] 等大模型打分机制，对输出内容进行多维度量化评估。
3. **解耦逻辑**：健康契约将“是否跑完”与“跑得好不好”这两个维度完全正交化，使得系统能够针对不同的失败模式采取差异化的修复策略，而非简单地进行全链路重跑。

### 应用场景
* **自动化内容生产流水线**：在涉及多阶段生成（如 wiki-build）的 Pipeline 中，利用健康契约确保每一环节的产出物质量，避免错误累积。
* **LLM 驱动的复杂任务处理**：当任务涉及多个 LLM 调用时，通过契约机制界定各阶段的边界，防止因单一环节的低分导致整个 Pipeline 的盲目重试。
* **系统监控与告警**：结合 [[sop-tg-notify]]，当健康契约的任一维度（流程或质量）被破坏时，系统可精准定位故障点并触发相应的告警或自动修复逻辑。
