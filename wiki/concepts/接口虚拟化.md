## 概念定义

接口虚拟化（Interface Virtualization）是 Harness Agent 架构中实现**解耦**的核心机制。它借鉴了操作系统对硬件的虚拟化思想——例如 `read()` 系统调用不关心底层是磁带还是 SSD——将复杂多变的执行环境（包括本地服务器、远程计算节点、云沙盒、容器等）抽象为一组统一、标准的操作接口。这样一来，上层推理引擎（Brain）只需调用这些虚拟化接口即可完成任务，完全无需了解底层环境的差异与实现细节。这种设计使得 Brain 与 Hands（执行层）之间形成松耦合关系：Brain 不必关心技能（Skill）在何处运行、如何运行，而执行层也可以独立演进、替换或扩展。接口虚拟化不仅降低了系统复杂度，还显著提升了可扩展性、可维护性和可靠性——任何一个底层环境的变更都不会波及 Brain 的逻辑，从而让 Harness Agent 在面对异构基础设施时表现得更加弹性和健壮。

## 技术细节

接口虚拟化的具体实现通常包括以下几个关键要素：

- **标准化接口定义**：通过约定输入、输出、错误处理、超时等协议，形成一套与具体实现无关的接口规范。例如，Harness 中每个 Skill 都具备固定的输入输出结构，Brain 通过统一的调用方式触发 Skill 执行。
- **适配层（Adapter Layer）**：负责将标准化调用转换为目标环境特有的 API 或命令。适配层维护了环境差异的映射逻辑，使 Brain 发出的指令无需修改即可在不同的执行引擎上生效。
- **状态与资源管理**：虚拟化接口通常需要隐式管理会话状态、资源生命周期（如内存、文件句柄、网络连接）以及并发控制。这些管理细节对 Brain 透明，由虚拟化层自动处理。
- **错误透明化**：底层环境的失败（如网络中断、沙盒崩溃）被虚拟化层捕获并转化为统一错误码或重试策略，上层 Brain 只感知到“调用成功/失败”，无需针对具体故障类型编写处理逻辑。

在 Harness Agent 中，接口虚拟化最典型的体现是：Brain 通过「动作先解析」机制将用户意图转化为标准化 Skill 序列，然后经由虚拟化层分发到本地或云端沙盒执行。无论底层运行在 Docker 容器、Kubernetes Pod 还是物理机，Brain 发出的指令格式完全一致。

## 应用场景

- **混合执行环境支持**：当 Harness Agent 需要同时在本地开发机、CI 服务器以及生产环境沙盒中运行相同的 Skill 时，接口虚拟化使得 Brain 无需区分环境类型，所有差异由虚拟化适配层处理。
- **技能市场与插件生态**：第三方开发者可以编写符合标准化接口的 Skill 插件，无需修改 Brain 核心逻辑。接口虚拟化降低了集成门槛，加速了生态扩展。
- **灰度发布与故障隔离**：通过虚拟化层可以按区域或用户群体切换 Execution Hand 的实现版本，而 Brain 的编排逻辑保持不变。一旦新版本出现问题，只需回滚适配层配置，无需修改 Brain 代码，实现快速恢复。
- **多租户资源隔离**：在多用户场景下，虚拟化层可为每个租户创建独立的沙盒环境（如不同的云账号或容器 namespace），Brain 只关心“将 Skill 下发到哪个租户的虚拟执行空间”，而资源分配与隔离完全由虚拟化层负责。
