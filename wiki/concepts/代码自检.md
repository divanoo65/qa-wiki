# 代码自检 (Code Self-Check)

### 概念定义
代码自检是指在自动化流水线（Pipeline）执行过程中，在调用大语言模型（LLM）生成内容后，引入的一层基于确定性逻辑的质量评估机制。该机制不依赖于 LLM 的概率性推理，而是通过编写 Python 脚本或配置规则，对生成产物的结构、格式及合规性进行硬性校验。其核心目标是确保输出内容符合预设的“健康契约”，例如检查 Frontmatter 字段的完整性、引用文件的有效性、内部链接（wikilink）的数量以及语言比例等。通过这种方式，系统可以在进入下一步骤前拦截低质量产出，从而降低无效的 LLM 重试成本，提升整个自动化流程的鲁棒性与可靠性。

### 技术细节
在 `wiki-build` 等关键流程中，代码自检通过以下逻辑实现：
1. **结构化校验**：解析生成的 Markdown 文件，验证 YAML Frontmatter 是否包含所有必填字段。
2. **引用完整性检查**：扫描文档中的 `sources` 字段或文件路径，通过文件系统 API 确认引用的资源文件真实存在。
3. **内容合规性度量**：利用正则表达式或统计方法计算中文比例，确保其满足 `min_chinese_ratio` 等健康契约阈值。
4. **链接密度分析**：统计文档中 [[wikilink]] 的数量，确保知识图谱的连通性。
5. **闭环修正机制**：若自检失败，系统会触发 LLM 进行最多 2 轮的自动修正；若仍未通过，则强制标记 `self_check: failed` 并提交，以便后续人工介入或触发[[失败模式]]分析。

### 应用场景
- **Wiki 自动化构建**：在生成知识库页面时，自动校验页面格式与链接质量，防止“孤岛页面”产生。
- **配置与模板校验**：在 `sop.yaml` 等配置文件变更时，通过自检确保 `health` 块中的参数（如超时时间、完成模式）符合规范。
- **流水线质量门禁**：作为 [[Pipeline 可靠性设计问答精粹]] 中提到的质量控制点，在 LLM 生成任务与最终提交之间建立一道“防火墙”，减少因 LLM 幻觉或格式错误导致的下游系统故障。
