# 根因路由 (Root Cause Routing)

### 概念定义
根因路由（Root Cause Routing）是指在自动化流水线（Pipeline）执行过程中，当评估器（Evaluator）检测到输出质量不达标时，系统不采取盲目的全局重跑策略，而是通过分析评估结果，将修复指令或重跑请求精准路由至导致问题的特定环节或上游节点的决策机制。该概念的核心逻辑在于识别“症状”与“根源”之间的非线性关系：在复杂的 LLM 应用链路中，下游阶段的评分低往往并非由当前阶段的逻辑错误引起，而是源于上游输入数据的质量缺陷、上下文缺失或指令偏差。通过根因路由，系统能够实现从“盲目重试”到“精准归因”的范式转变，从而显著降低 Token 消耗并提升系统的整体鲁棒性。

### 技术细节
根因路由的实现依赖于对流水线各阶段（Stage）的深度监控与状态追踪：
1. **故障诊断层**：当 `wiki-evaluate` 给出低分时，系统触发诊断逻辑，对比输入上下文与预期输出的差异。
2. **路由决策表**：根据诊断结果，系统查询预设的路由规则。例如，若评估发现“事实性错误”，路由逻辑可能指向数据检索层；若发现“格式错误”，则路由至 Prompt 优化层。
3. **状态回溯**：利用 [[健康契约]] 机制，检查各阶段的输入输出契约是否被破坏，从而定位是哪个环节产生了“脏数据”或“逻辑漂移”。
4. **差异化重跑**：仅对被路由定位的特定环节进行参数调整（如调整 Temperature 或修改 Prompt）后重跑，而非对整个流水线进行无差别的全量重试。

### 应用场景
* **复杂文档生成流水线**：在涉及多步推理的 [[pipeline-creator]] 中，当最终生成的报告质量不佳时，通过根因路由判断是检索阶段召回不足，还是生成阶段的逻辑推理错误。
* **自动化内容审核系统**：当审核结果被判定为误报时，路由机制可将样本回传至特定的 [[Gemini]] 模型实例进行二次校准，而非重新执行整个审核流程。
* **异常告警处理**：结合 [[sop-tg-notify]]，在检测到特定阶段失败时，根据根因路由的结果，将修复建议直接推送给对应的维护人员，实现人机协同的故障闭环。
