# 解耦原则

## 概念定义
解耦原则（Decoupling Principle）在 Harness Agent 架构中被视为系统的核心灵魂。其本质是通过“虚拟化”手段，在 Agent 的决策中枢（Brain）与具体执行单元（Hands/Skill）之间建立一层标准化的抽象接口。这种设计借鉴了操作系统的设计哲学：正如操作系统通过统一的系统调用（如 `read()`）屏蔽了底层存储介质（磁带或 SSD）的差异，Harness Agent 通过对执行环境的虚拟化，使得 Brain 在下达指令时无需感知底层的运行环境是本地环境还是云端沙盒。这种架构上的彻底分离，确保了决策逻辑与执行逻辑互不依赖，从而赋予了系统极高的灵活性，使得任何一方的变更或升级都不会引发连锁反应，极大地降低了系统维护的复杂性。

## 技术细节
- **虚拟化接口**：通过标准化接口定义输入与输出，将复杂的执行逻辑封装在原子化的 [[Skill]] 内部。
- **职责分离**：
    - **Brain 层**：负责全局的逻辑编排与决策，通过 [[编排]] 决定 Skill 的执行顺序（顺序执行或 DAG 结构）。
    - **Hands 层**：即 Skill 集合，负责执行具体的原子操作，内部不包含任何条件分支或决策逻辑。
- **互不依赖**：Brain 不直接调用底层 API，而是通过中间层与 Skill 交互，实现了执行环境的透明化。

## 应用场景
- **跨环境部署**：当 Agent 需要在不同的基础设施（如本地开发机、生产集群、云端沙盒）之间迁移时，无需修改 Brain 的逻辑，只需更换对应的 Skill 实现即可。
- **组件热插拔**：在需要升级或替换特定功能模块（如更换不同的 API 客户端或执行引擎）时，只需确保新 Skill 符合接口契约，即可实现无缝替换。
- **系统可靠性保障**：由于 Skill 内部逻辑固定且原子化，通过解耦可以有效隔离执行层故障对决策层的影响，便于进行单元测试与故障排查。
